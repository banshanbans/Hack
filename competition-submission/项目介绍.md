# 安居守护（安心家 AI）项目介绍

> 一句话介绍：上传家庭空间照片、视频代表帧，或使用实时相机和 iPhone 空间扫描，AI 帮助家庭发现画面中可见的跌倒、通行、支撑、照明与使用风险，标出具体位置，并生成可执行的 A/B/C 整改方案和规则化参考预算。

## 1. 我们聚焦的真实需求

父母年龄增长后，行动能力、平衡能力和视力都可能发生变化。但家中的松动地垫、过高门槛、通道杂物、洗浴区缺少支撑、常用物品摆放过高等问题，往往会因为“一直都这样”而被家人忽略。

现有适老化服务常在用户已经决定装修后才介入，普通家庭缺少一个低门槛的“先发现问题、再一起决定怎么改”工具。我们解决的不是“让 AI 给家里打一个分”，而是以可追溯证据为起点，把拍摄、发现、确认、选方案和家庭协作串成完整用户链路。

### 典型场景

一位子女发现父母腿脚不便，近期还有过跌倒，但不知道应先改哪里。他可以先上传卫生间照片，系统检查照片质量，定位画面中的可见风险，再结合父母的行动能力、跌倒情况和居住状态，生成按优先级排列的风险清单。家人可比较“当天止险”“性价比改造”“专业改造”三档方案，选择后得到统一的整改清单和参考预算，用于家庭讨论。

## 2. 目标用户

- 主要用户：30–55 岁、关注父母居家安全的成年子女。
- 直接受益者：老人本人，尤其是行动受限、使用手杖/助行器、有跌倒史或独居的长者。
- 协作用户：其他家庭成员、社区养老服务人员、适老化改造服务人员。
- 延展场景：在游园会等线下体验场景中，工作人员使用 iPhone 分 Zone 扫描，辅助发现画面中可见的通行和场地风险。

## 3. 用户如何完成一次检查

### 家庭 H5 主链路

```text
了解产品与隐私边界
  → 选择照片、视频代表帧或实时相机
  → 填写家人行动能力、跌倒情况和居住状态
  → 选择房间并上传 1–6 张图片
  → 图片质量检查与补拍建议
  → AI 发现并定位可见风险
  → 用户确认、否认或修正风险位置
  → 查看参考分、独立覆盖度和 A/B/C 方案
  → 选择整改方案，生成家庭改造清单与参考预算
  → 分享给家人讨论
```

已实现的 H5 覆盖卫生间、卧室、客厅、厨房、走廊和阳台六类房间，支持多房间任务、刷新恢复、风险反馈和家属报告。

### 实时相机与视频

- 视频默认在浏览器本地解码，只选择 3–6 张代表帧，不上传完整原视频。
- 实时相机先在本地做清晰度、亮度、场景变化和重复帧门控，只在质量合格、画面有变化、无进行中请求且未超限时发起 AI 检查。
- 相机中的即时内容只是临时建议，不计分、不定最终等级、不直接进入正式报告。用户确认保存的代表帧才进入正式评估链路。

### 游园会 iPhone AR 链路

```text
选择 entrance / main_aisle / booth / rest_area Zone
  → ARKit / RoomPlan 扫描与本地质量、变化门控
  → 云端 Turbo 发现可见候选
  → 云端 Pro 确认、拒绝、合并或修正候选
  → 服务端规则确定等级、扣分、方案和预算
  → 有可靠深度时建立世界锚点，无深度时降级为二维证据卡
  → 生成按优先级排列的辅助报告
```

## 4. AI 在链路中具体做了什么

我们没有让大模型直接给家庭打分或自由生成报价，而是将 AI、规则引擎、Agent 和前端分成四个责任边界：

| 层级 | 具体责任 |
|---|---|
| AI 模型 | 判断图片是否可用；理解房间中可见设施与通道；发现风险候选；返回证据、置信度以及 0–1 归一化 bbox/polygon |
| 确定性规则 | 校验风险代码和证据；根据房间、用户档案和规则版本决定最终等级和扣分；单独计算覆盖度；匹配 A/B/C 方案；从 PriceRule 合计预算 |
| Assessment Agent | 管理评估 Session 和多房间状态；按流程调用各项 Skill；处理超时、空结果、重试和用户反馈；保留模型、Prompt、规则版本和请求状态 |
| 前端 | 按结构化数据稳定渲染风险标注、分数、覆盖度、整改方案和报告；支持用户修改位置和提交反馈；不执行模型生成的 SVG/HTML |

### Skill / Agent Workflow

```text
MediaQualityCheckSkill
  → FrameSelectionSkill（视频/连续帧）
  → SceneUnderstandingSkill
  → RiskDetectionSkill
  → RegionGroundingSkill
  → RiskNormalizationSkill（评分前跨帧去重）
  → 风险白名单与证据 Schema 校验
  → 确定性评分 + 独立覆盖度
  → RecommendationSkill
  → PriceExplanationSkill
  → ReportSummarySkill
```

这套编排已整理为独立可复用 Skill 压缩包，可以通过标准 manifest 输入调用安居守护 v2 API，完成建档、图片上传、异步分析、结果校验、方案选择和报告获取。

## 5. 用户最终获得的价值

### 从“感觉可能有问题”到“知道问题在哪里”

每个进入正式报告的风险都必须有可追溯证据区域。用户可以直接在原图上看到问题位置和原因，而不是只得到一段泛化建议。

### 从“不知道先改哪个”到“有优先级的任务”

风险等级和扣分会结合老人的行动能力、跌倒情况、居住状态以及证据可信度，帮助家庭优先处理最值得行动的问题。用户否认误报后，规则引擎会重新计算，而不是由前端修改一个显示数字。

### 从“建议太空泛”到“可以立即讨论的方案”

- A：立即止险，低成本、通常可当天完成，但改善有限。
- B：推荐改造，以性价比为优先，可高亮但不自动选择。
- C：专业改造，更长期、系统，可能需要施工或专业安装。

用户可在安全性、预算、时间和施工复杂度之间做出适合自己家庭的选择。金额来自版本化价格规则，不由模型自由编造；清单还会对多个风险共用的同一整改动作做预算分组去重。

## 6. 核心创新点

### 6.1 模型理解，规则裁决

大模型擅长理解复杂画面，但安全等级、分数和价格需要稳定、可解释、可测试。因此我们把模型限定在“发现、定位和解释候选”，把最终裁决交给版本化规则。相同输入和规则版本会得到相同结果。

### 6.2 安全分和拍摄覆盖度彻底分开

“没拍到”不等于“没问题”。系统不会因为用户没拍全而直接扣安全分，但会降低覆盖度；覆盖不足时只展示“当前已检查区域安全参考分”，不宣称得到全屋结论。

### 6.3 证据优先，支持人机共同修正

没有 bbox、polygon、RoomPlan 对象/表面 ID、快照引用、世界坐标或用户手动圈选之一的候选，不会直接进入正式结果。用户可以否认风险或重新圈选位置，反馈会留在评估记录中并触发规则重算。

### 6.4 连续帧不等于重复扣分

视频和实时相机中，同一物理问题可能被多张帧反复看到。系统会保留多个证据视角，但在评分前合并为 canonical risk，只扣分一次。

### 6.5 Turbo 发现 + Pro 复核 + AR 空间定位

在 iPhone 游园会路径中，Turbo 模型快速发现候选，Pro 模型在进入正式评分前复核。候选 bbox 经过方向和裁剪逆变换后，再与历史帧位姿、相机内参和深度图关联。有可靠深度才创建世界锚点，否则保留二维证据，避免生成虚假三维定位。

### 6.6 隐私和正式/Demo 能力边界从架构层隔离

浏览器不保存模型密钥，原视频默认不上传，相机临时帧默认不持久化，模型返回会经过动态白名单和 Schema 校验。正式 Provider 失败时不回退到 Demo；所有 Mock 只能通过显式开关启用。

## 7. 当前实现进度

### 已实现的代码能力

- React/TypeScript 移动端 H5 P01—P09 照片主流程，包括档案、六类房间、多图上传、异步分析、风险位置、用户反馈、方案和报告。
- FastAPI/Uvicorn v2 Assessment API，使用 SQLite 保存评估、房间、媒体、任务、风险、方案和分享状态。
- 火山方舟与 OpenAI Responses 视觉 Provider 适配，包含结构化输出、风险代码白名单、超时、并发门控、安全错误和 request ID。
- 确定性评分、独立覆盖度、风险反馈重算、A/B/C 结构化方案、预算分组去重和预计改善区间。
- H5 视频本地解码与代表帧、实时相机临时建议及单请求门控。
- UIKit iPhone 端 RoomPlan/ARKit 空间扫描、四 Zone 游园会路径、Turbo/Pro 云端链路、历史帧深度反投影、风险证据卡、世界锚点和规则化报告。
- Swift 领域测试、Python/FastAPI 测试、React/Vitest 测试、产品文案与规则校验，以及 iOS 无签名编译记录。
- 项目核心家庭安全评估能力已封装为独立 Skill，包含 `SKILL.md`、契约文档、安全边界和可执行编排脚本。

### 尚未完成或尚待外部验证

- 整改前后复查对比闭环尚未完成。
- 尚未建立获授权的家庭、视频、实时相机与游园会风险评测集；当前不对真实模型召回率、误报率或定位准确度作未经评测的效果声明。
- H5 视频与实时相机仍需完成 Safari/Chrome 多设备外部验收。
- iPhone 旋转图片、模型 bbox、深度图与世界锚点的整体坐标链路，仍需在 LiDAR 真机进行完整验证。
- 弱网、VoiceOver、Dynamic Type、连续三次游园会现场演示和长时间扫描内存表现仍需真机/现场验收。
- PDF 导出、按城市价格、跨房间永久地图、商品服务和训练管线不属于当前已完成范围。

## 8. 技术架构

| 端/层 | 技术与责任 |
|---|---|
| H5 | React 19 + TypeScript + Vite；移动优先，承担照片、视频和实时相机用户旅程 |
| iOS | UIKit + RoomPlan + ARKit + RealityKit；承担空间扫描、设备质量门控、深度定位和 AR 证据展示 |
| 领域层 | Swift Package `AnjuCore`；承担风险模型、规则、证据、去重、状态和报告排序 |
| 服务端 | FastAPI + Uvicorn + SQLite；承担 Assessment Session、媒体、任务、Provider、评分、覆盖度、价格和报告 |
| AI Provider | 火山方舟 / OpenAI Responses；密钥仅存放在服务端，模型输出必须通过结构化 Schema 和业务白名单 |
| 规则数据 | 版本化 JSON；存放风险、证据、评分、A/B/C 方案和 PriceRule，不将数字写进 Prompt |

## 9. 后续延展空间

1. **完成整改后复查**：将整改前后的证据区域进行可追溯对比，输出已解决、未解决和新发现风险，实现真正的行动闭环。
2. **建立授权评测体系**：记录分房型、分风险、分光照和分设备的召回、误报、定位、去重与建议可用性指标，让模型优化有数据根据。
3. **城市与房屋条件化价格**：在不让模型自由报价的前提下，增加城市、房屋类型和安装条件维度的 PriceRule。
4. **家庭协作与社区服务**：支持家人分工、备注、进度更新和社区上门复核，但保持选择权和数据控制权在用户手中。
5. **更多端的 Skill 复用**：将媒体质量、风险归一化、整改建议和复查对比继续拆成可组合 Skill，供社区养老、家政巡检或适老化服务系统通过同一契约接入。

## 10. 产品边界与负责任声明

安居守护是基于用户所提供画面的环境安全辅助筛查工具，不是医疗诊断、建筑验收、无障碍认证、消防检查或施工报价工具。它只能分析画面中可见的内容，不会将未拍摄区域视为安全，也不对墙体、承重、防水、暗管和施工条件作照片外判断。

所有金额均是规则库中的参考区间，实际费用以现场条件和服务方确认为准。高风险项或涉及固定、用电、防水、墙体的整改，应由有经验的专业人员结合现场进一步确认。

---

**项目核心原则：先让用户看见问题，再解释为什么有风险；最终目标不是得到一个高分，而是帮助家庭完成最重要的一项整改。**
